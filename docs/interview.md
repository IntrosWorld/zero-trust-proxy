# Explain this project

- **HTTPS request:** curl opens TCP to the proxy, sends CONNECT plus proxy auth, the worker validates policy, asynchronously resolves every destination address, validates/pins them, performs nonblocking connect, returns 200, reads the TLS ClientHello, checks SNI, then relays ciphertext. The client checks the origin certificate.
- **Forward versus reverse proxy:** this proxy accepts the client's chosen destination subject to egress policy. A reverse proxy represents a server and chooses configured backends.
- **TCP:** SYN/SYN-ACK/ACK establish a connection; FIN ends one direction, so two directions may close at different times. RST aborts. TIME_WAIT retains the tuple to keep delayed packets from an old connection out of a new one.
- **URL path:** DNS selects addresses; TCP establishes transport; TLS authenticates/encrypts; HTTP carries the application exchange. CONNECT creates the TCP tunnel before TLS begins.
- **epoll versus threads/select/poll:** select/poll scan descriptor sets; epoll returns ready events. Per-connection threads also reserve stacks and increase scheduling overhead. Worker epoll loops retain bounded per-connection state instead. This implementation needs about two 64 KiB buffers per active connection before kernel buffers and metadata.
- **Edge versus level:** level mode repeatedly reports current readiness. Edge mode requires draining readiness; ONESHOT rearming explicitly rechecks it when a fairness budget or backpressure stops a drain.
- **Nonblocking connect:** EINPROGRESS means wait, not failure. EPOLLOUT is only a notification; SO_ERROR determines success. Only pinned sockaddr values are used.
- **REUSEADDR versus REUSEPORT:** REUSEADDR helps bind/restart semantics. REUSEPORT lets independent worker listeners bind the same address and lets the kernel distribute connections.
- **eventfd/timerfd:** each converts cross-thread notifications or time passage into fd readiness handled by epoll. SIGPIPE is suppressed so a peer closing during send cannot kill the process.
- **Backpressure:** a failed/partial send leaves bytes queued. Source read interest is disabled until the destination drains them. On FIN, pending bytes flush before propagating SHUT_WR.
- **DNS rebinding/SSRF:** validate every answer, reject internal ranges and connect directly to the validated sockaddr. A later DNS change cannot change that connection. A raw IP or IPv4-mapped IPv6 cannot skip address checks.
- **SNI/domain fronting:** a ClientHello reveals a requested TLS server name in ordinary TLS. Matching it to CONNECT stops a second visible hostname from silently selecting a different destination. No SNI/ECH limits this guarantee, and HTTP Host inside TLS is invisible.
- **Authentication:** early-return string comparisons disclose matching prefixes. Accumulating differences avoids that behavior. Bearer credentials require a trusted client-to-proxy transport.
- **Token bucket:** tokens refill with elapsed monotonic time up to burst capacity; each request spends one token. Injected timestamps test refill and backward-time edge cases. State is per worker, so document the aggregate allowance.
- **RAII:** a move-only Fd closes on destruction; unique_ptr owns each connection; shared_ptr keeps config snapshots alive. string_view is used only while its source storage is valid. A connection ID protects against stale asynchronous results, independently of fd-number reuse.
- **Races:** TSan detects unsynchronized memory access. Logical races can remain in synchronized code; for example an old DNS result must not affect a new connection. Relaxed counters are sufficient because they are independent statistics, not publication flags.
- **Tools:** ASan checks invalid memory access; UBSan checks undefined behavior; TSan checks data races; Valgrind checks memory errors/leaks; fuzzing generates parser inputs. The raw results are committed, including tool-environment limitations.
- **A real optimization:** Callgrind showed 97.43% of instructions in BodyFramer during the fixed-body microbenchmark. Counting a block's bytes instead of scanning every payload byte removed that hotspot. This is a framing microbenchmark, not a network-throughput claim.
- **A debugging example:** the first concurrent integration run hit upstream connect timeouts. Access logs showed the connections timing out at the test server; its listen backlog was five. Raising the backend fixture backlog solved the failure. Separately, review found RDHUP could repeatedly wake a write-blocked half-closed socket; EPOLLIN EOF detection avoids subscribing to that persistent condition.
- **Scaling further:** first measure limits, not just add workers. The local Python backend and client share this CPU, DNS uses a finite resolver pool, each connection opens two sockets, logging uses a bounded queue, and RSS/kernel buffers grow with connections. Raise fd limits deliberately; a larger deployment needs multiple processes/hosts, shared policy distribution, distributed limits and explicit failure behavior.
- **Nagle and zero-copy:** TCP_NODELAY reduces batching delay for small forwarded requests. splice could avoid copying bulk tunnel bytes through userspace but requires pipes and special EOF/backpressure handling. It is an unimplemented stretch feature; no benefit is claimed.
