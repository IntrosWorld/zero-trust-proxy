# Explain this project

- **HTTPS request:** curl opens TCP to the proxy, sends CONNECT plus proxy auth, the worker validates policy, asynchronously resolves every destination address, validates/pins them, performs nonblocking connect, returns 200, reads the TLS ClientHello, checks SNI, then relays ciphertext. The client checks the origin certificate.
- **Forward versus reverse proxy:** this proxy accepts the client's chosen destination subject to egress policy. A reverse proxy represents a server and chooses configured backends.
- **TCP:** SYN/SYN-ACK/ACK establish a connection; FIN ends one direction, so two directions may close at different times. RST aborts. TIME_WAIT retains the tuple to keep delayed packets from an old connection out of a new one.
- **URL path:** DNS selects addresses; TCP establishes transport; TLS authenticates/encrypts; HTTP carries the application exchange. CONNECT creates the TCP tunnel before TLS begins.
- **epoll versus threads/select/poll:** select/poll scan descriptor sets; epoll returns ready events. Per-connection threads also reserve stacks and increase scheduling overhead. Worker epoll loops retain bounded per-connection state instead. This implementation needs about two 64 KiB buffers per active connection before kernel buffers and metadata.
- **Edge versus level:** level mode repeatedly reports current readiness. Edge mode requires draining readiness; ONESHOT rearming explicitly rechecks it when a fairness budget or backpressure stops a drain.
- **Nonblocking connect:** EINPROGRESS means wait, not failure. EPOLLOUT is only a notification; SO_ERROR determines success. Only pinned sockaddr values are used.
- **REUSEADDR versus REUSEPORT:** REUSEADDR helps bind/restart semantics. REUSEPORT lets independent worker listeners bind the same address and lets the kernel distribute connections.
- **eventfd/timerfd:** each converts cross-thread notifications or time passage into fd readiness handled by epoll. SIGPIPE is suppressed so a peer closing during send cannot kill the process.
- **Backpressure:** a failed/partial send leaves bytes queued. Source read interest is disabled until the destination drains them. On FIN, pending bytes flush before propagating SHUT_WR.
- **DNS rebinding/SSRF:** validate every answer, reject internal ranges and connect directly to the validated sockaddr. A later DNS change cannot change that connection. A raw IP or IPv4-mapped IPv6 cannot skip address checks.
- **SNI/domain fronting:** a ClientHello reveals a requested TLS server name in ordinary TLS. Matching it to CONNECT stops a second visible hostname from silently selecting a different destination. No SNI/ECH limits this guarantee, and HTTP Host inside TLS is invisible.
- **Authentication:** early-return string comparisons disclose matching prefixes. Accumulating differences avoids that behavior. Bearer credentials require a trusted client-to-proxy transport.
- **Token bucket:** tokens refill with elapsed monotonic time up to burst capacity; each request spends one token. Injected timestamps test refill and backward-time edge cases. State is per worker, so document the aggregate allowance.
- **RAII:** a move-only Fd closes on destruction; unique_ptr owns each connection; shared_ptr keeps config snapshots alive. string_view is used only while its source storage is valid. A connection ID protects against stale asynchronous results, independently of fd-number reuse.
- **Races:** TSan detects unsynchronized memory access. Logical races can remain in synchronized code; for example an old DNS result must not affect a new connection. Relaxed counters are sufficient because they are independent statistics, not publication flags.
- **Tools:** ASan checks invalid memory access; UBSan checks undefined behavior; TSan checks data races; Valgrind checks memory errors/leaks; fuzzing generates parser inputs. The raw results are committed, including tool-environment limitations.
- **A real optimization:** Callgrind showed 97.43% of instructions in BodyFramer during the fixed-body microbenchmark. Counting a block's bytes instead of scanning every payload byte removed that hotspot. This is a framing microbenchmark, not a network-throughput claim.
- **A debugging example:** the first concurrent integration run hit upstream connect timeouts. Access logs showed the connections timing out at the test server; its listen backlog was five. Raising the backend fixture backlog solved the failure. Separately, review found RDHUP could repeatedly wake a write-blocked half-closed socket; EPOLLIN EOF detection avoids subscribing to that persistent condition.
- **Scaling further:** first measure limits, not just add workers. The local Python backend and client share this CPU, DNS uses a finite resolver pool, each connection opens two sockets, logging uses a bounded queue, and RSS/kernel buffers grow with connections. Raise fd limits deliberately; a larger deployment needs multiple processes/hosts, shared policy distribution, distributed limits and explicit failure behavior.
- **Nagle and zero-copy:** TCP_NODELAY reduces batching delay for small forwarded requests. splice could avoid copying bulk tunnel bytes through userspace but requires pipes and special EOF/backpressure handling. It is an unimplemented stretch feature; no benefit is claimed.

Do not present the supplied spec's placeholder resume numbers as results. Use README measurements and their qualifications, and explain the code yourself before an interview.

## Kubernetes extension

- **Pod / ReplicaSet / Deployment:** a pod is the scheduling unit; a ReplicaSet maintains its count; a Deployment manages ReplicaSets during updates. A ClusterIP Service supplies a stable internal address and routes to ready endpoints. NodePort exposes a port on nodes; this demo uses ClusterIP and explicit local port-forwards. Namespaces organize resources; they are not security boundaries without policy/RBAC.
- **Probes:** startup allows initialization time, liveness detects an unresponsive process, readiness controls whether it receives new Service traffic. Failing liveness just because Redis or the policy service is unavailable would restart otherwise useful fail-static replicas.
- **Resources:** requests guide scheduling and give HPA its CPU-utilization denominator. Limits cap consumption: CPU can be throttled; exceeding memory limits can cause OOMKill. Here each proxy requests 100m CPU and HPA targets 60%, so a modest sustained workload can trigger scaling.
- **ConfigMap / Secret:** ConfigMaps hold ordinary configuration; Secrets carry credentials and are mounted only where needed. Kubernetes Secret base64 encoding is not encryption. This demo does not claim etcd encryption at rest; local credential files are excluded from Git and backups of the source repository.
- **Updates and placement:** maxSurge 1 creates a replacement before removing an old pod; maxUnavailable 0 gates updates on availability. A minimum-two PDB protects voluntary evictions, not crashes. Topology spread distributes pods across the two workers, which still share one physical host.
- **Shutdown:** kubelet sends SIGTERM and eventually SIGKILL if the grace period expires. The process marks itself unready, allows endpoint changes to propagate, closes listeners and drains bounded in-flight work. Existing tunnels longer than the drain window can still fail.
- **Control/data planes:** policy administration and history live in the Python/SQLite service. The C++ replicas enforce immutable snapshots independently. Version numbers reject stale/conflicting updates, hashes compare content, and heartbeat leases reveal stale replicas. This is eventual consistency, without an atomic fleet-wide switch or a guaranteed convergence bound during partitions.
- **Outages:** policy fail-static means retain the last validated policy. Redis fallback retains local limits, but weakens the global cap and changes identity from authenticated token to source IP per worker. Fail-closed mode returns 503 instead. Neither behavior should be described as fully unrestricted fail-open access: destination checks remain active.
- **Redis atomicity:** independent read/refill/write operations race across pods. A Lua script performs the whole token-bucket update atomically, using Redis time. Persistent connections and helper threads keep Redis waiting off the epoll loop. The cost is an extra request dependency: the local latency comparison measured 2.16 ms more p50 and 8.16 ms more p99, including shared-host scheduling effects.
- **Polling:** ETag/304 avoids resending unchanged policies; long-polling wakes on updates. Jitter reduces synchronized reconnects. The measured roughly 0.6-second fleet checks include API, kubectl and enforcement-probe overhead, so they are not pure network propagation latency.

## Questions to rehearse

1. **A pod dies mid-request?** Its established connections can reset. Readiness and draining help planned updates, not sudden power loss. E5 used partial-header requests: 41 failed without the drain settings, zero with them. E1 measured a 2.25-second replacement-ready time in this local cluster.
2. **How do you know a policy is enforced?** Compare each ready pod's `/policy` version and SHA, check rollout heartbeat leases, and probe the newly denied destination. E2 did all three for 20 block updates per polling mode. During a partition, a pod keeps its old policy and reports errors rather than silently accepting unvalidated data.
3. **Why Redis, and what if it dies?** Local buckets multiply with workers/replicas; Redis shares one atomic bucket per authenticated identity. E6 admitted nine requests across three replicas with the shared bucket versus 53 with local buckets. E7 exercised local fallback and recovery. Restarting this non-persistent Redis grants fresh bursts; production needs an explicit durability/availability design.
4. **Why didn't throughput increase smoothly?** All nodes, monitoring, the two-core client and single Redis share one host. E3 measured 3,815 / 2,452 / 966 / 5,476 decisions per second at 1 / 2 / 3 / 6 replicas. That noisy run does not establish a scaling law or identify one proven bottleneck; repeat with isolated clients and profile CPU/throttling/Redis before claiming linear scaling.
5. **What prevents bypass?** Calico enforces default-deny app egress, allowing DNS and the proxy only. E8's direct HTTPS attempt timed out while the authenticated proxy path succeeded with origin certificate verification. YAML alone would not enforce this with a non-enforcing CNI.
6. **What changes across regions?** Use authenticated encrypted service links, per-workload identity, replicated policy storage with a defined consistency model, highly available Redis or regional quotas, and independent regional failure domains. Decide whether global quota accuracy or partition availability wins; simply adding more kind nodes does not solve those issues.
