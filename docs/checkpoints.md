# Verified checkpoints

- M1: CMake presets, RAII descriptors and epoll echo foundation. ASan/UBSan build and real socket echo smoke passed. The echo executable is replaced by the proxy in M3.
- M1 verification note: the first smoke attempt was sandbox-blocked; the subsequent approved run outside the sandbox passed without sanitizer diagnostics.
- M2: seven GoogleTest cases pass, covering every header split, bytewise CONNECT, framing ambiguity, limits, stripping, chunked and fixed bodies.
- M3–M9 implementation checkpoint: integrated the forwarding state machine with policy, DNS, SNI, worker isolation, authentication, limits, metrics and lifecycle together so no insecure forwarding-only binary is shipped. Sixteen unit cases and 21 real-socket integration cases pass. HTTP GET/POST/chunked, curl HTTP/HTTPS, TLS download SHA-256, fragmented ClientHello, SNI blocking, four workers, limits, reload and log checks are verified. Dedicated hardening and expanded scenario evidence follow in separate checkpoints. Initial concurrency failure was a five-entry Python backend backlog; increasing the fixture backlog to 256 made all clients succeed.
- M5–M9 expanded verification: 37 integration tests pass, including all 16 attack categories, five legitimate categories, 2,000 sockets, dual-family listeners, DNS mapping changes, an 8 MiB half-close/backpressure check, 4 MiB streaming upload, invalid reload and graceful drain. The L3 smoke download is 1 MiB; a separate benchmark runs 500 MiB.
- M10 hardening: full 37-case suite passes under ASan/UBSan and TSan. On this host TSan requires `setarch x86_64 -R` (per-process ASLR workaround). Four Valgrind integration scenarios report zero bytes at exit and zero errors. clang-tidy found one unnecessary config string copy, now corrected. Recorded a real 314-byte OpenSSL ClientHello as a unit/fuzz seed. Initial HTTP fuzz run: 697,281 executions; SNI: 1,176,277; no input-triggered crashes. Clang ASan had one pre-input startup crash with ASLR enabled; the SNI run succeeded with per-process ASLR disabled. Final reproducible runs follow after optimization.
- M11 optimization: Callgrind attributed 92,278,790 / 94,708,115 instructions (97.43%) to fixed-body framing. Replacing per-byte scans with a checked block-length subtraction reduced total instructions for the same 8 MiB accounting workload to 2,434,776. The 256 MiB framing-only timing went from 0.211128 seconds to 0.000022623 seconds; this is bookkeeping, not payload copying or network throughput. Perf was unavailable (`perf_event_paranoid=4`), so Callgrind supplied reproducible profiling evidence.
- M12 integration: the actual SentinelAgent EgressClient, subclassed only to configure the external proxy and TLS verification, completed a trusted-certificate local HTTPS request. Its existing DLP blocked a synthetic password before transmission, its destination policy blocked an unknown host, and a C++ proxy denial surfaced as an agent error. Evidence is in `bench/results/sentinel.json`; the external SentinelAgent checkout was not modified.
- Configuration checkpoint: strict JSON parsing now supports unicode escapes/surrogate pairs and exponent numbers, rejects duplicate keys, unknown keys, invalid types/ranges, NUL paths/tokens and malformed host patterns, and canonicalizes host rules. System-DNS fallback, no-SNI TLS, authenticated non-loopback bind and JSON validation bring integration coverage to 41 tests. All 17 unit tests and all 41 integration tests pass in ASan/UBSan and TSan builds. Final fuzz runs: HTTP 341,762 and SNI 1,488,004 executions, with no crashes (30-second runs, raw output retained).
- Final review: added an eighteenth unit test and fixed idle bucket eviction for rates slower than a ten-minute refill. Eviction now waits until the full configured burst would have replenished. All 18 unit tests and 41 integration tests pass in release, ASan/UBSan and TSan after this fix. The 30-second benchmark runs never exercise ten-minute eviction; their exact source snapshot and binary SHA-256 remain recorded in `environment.json`.
- Reload-test checkpoint: a final Valgrind rerun exposed a fixture race: successful client connect does not imply the worker has accepted the socket and captured a config snapshot. Replaced a 50 ms sleep with the accepted-connection counter and a longer header deadline for this non-timeout test. The failing report is preserved in `valgrind-reload-before-fix.txt`. Release, ASan and TSan each pass all 41 integration tests after the fixture fix; all four final Valgrind scenarios pass with no leaks/errors.
- Final benchmark checkpoint: ten 30-second wrk runs completed without socket/HTTP errors. Four workers at 100 clients measured 10,090.71 requests/sec, p50 9.63 ms and p99 13.76 ms. A byte-exact 500 MiB TLS download measured 951.16 MiB/s; 1,000 idle connections added 132.3 KiB RSS each. Raw data and scaling plots are saved. A stable 100-client snapshot matched the active gauge to 100 accepted ESTAB sockets. At this checkpoint Docker and hosted GitHub Actions were unexecuted; optional splice/seccomp and perf flame graphs are not claimed.

- Docker packaging checkpoint: added a non-root multi-stage image, Linux Compose deployment, health check, resource restrictions, persistent logs, full integration-suite adapter and deployment lifecycle checks. Python/shell syntax, YAML parsing and whitespace checks pass. Engine installation and runtime validation were initially pending desktop authentication; completed below.

- Docker validation checkpoint: installed Docker Engine 29.8.2 and Compose on the Linux ext4 drive. The initial image build exposed this network's HTTP repository timeout; changed to HTTPS with a CA bundle bootstrapped from the official Alpine image (TLS and package signature verification remain enabled). The image builds successfully and all 41 integration cases pass in 27.32 seconds. Compose verifies healthy startup, policy denial, SIGHUP, exit code 0 on stop, persistent logs and configured restrictions. The normal local Compose service is healthy on 127.0.0.1:3128 with admin health on 127.0.0.1:9100. ## Kubernetes branch

- K1: pinned kind, kubectl, Helm and a Kubernetes node image; installed Calico on one control-plane node and two workers. All three nodes Ready. Everything runs on the Linux drive, on one physical host. Operator CRDs must be applied before the Calico operator.
- K2/K9: generated plain manifests as an instructional baseline and deployed the complete Helm chart with three replicas, ClusterIP, mounted Secrets, resources, probes and restricted pod security. Real TLS-verified HTTPS succeeds from the restricted app pod and from the host through a Kubernetes port-forward. The plain baseline was not installed separately. `enableServiceLinks: false` avoids injected service environment variables colliding with application configuration.
- K3: readiness and bounded SIGTERM draining are covered by real-process integration tests. E5's partial-header rolling-update workload had 41 failures without readiness/draining and zero with them; E1 measured 2.255 seconds to replacement readiness under load. These do not promise unlimited tunnel preservation or crash-free failover.
- K4: versioned SQLite policy history/audit, admin/read authorization, rollback as a new version, ETag/long-poll sync, heartbeat leases and fail-static enforcement implemented. E2 completed 20 updates per mode with version/hash and denial checks on all three replicas. E9 passed after waiting for actual outage and fixing Python PID 1 signal handling; the first failed run is retained. E10 rejected invalid API input and a conflicting same-version response.
- K5: bounded asynchronous Redis RESP helpers and atomic Lua buckets share authenticated-identity limits across pods. E6 admitted nine requests under the shared bound versus 53 with local limits; E7 verified local fallback and Redis recovery. Integration tests cover a fragmented fake Redis server, shared identity, fallback and fail-closed behavior.
- K6: Prometheus ServiceMonitors, alerts and a ten-panel Grafana dashboard installed. Scrape targets were verified up and a real dashboard screenshot was captured during wrk load. The local operator's TLS listener and admission webhook are disabled together.
- K7: metrics-server, CPU HPA, PDB and topology spread installed. E3 records all four replica counts, including regressions. E4 observed 3 → 6 → 3 replicas under 90 seconds of load and a cooldown period. Helm 4 uses explicit conflict reconciliation for fields intentionally changed by the experiment harness.
- K8: Calico default-deny NetworkPolicies enforced in app, proxy and monitoring namespaces. E8's direct HTTPS request failed and authenticated proxy HTTPS succeeded. DNS remains allowed; this is not a DNS-exfiltration defense.
- K10 local verification: 21 GoogleTest cases and 51 pytest cases (46 proxy integrations plus five control-plane tests) pass in release, ASan/UBSan and TSan. Static analysis passes all 21 translation units after simplifying a shared-pointer initialization that triggered an analyzer false positive. Chart lint, source formatting and script syntax checks pass. The kind CI job and safe create/test/delete harness are implemented, but the fresh-cluster harness has not been run end-to-end locally and hosted GitHub Actions has not run; those remain explicit verification limits, not claimed green CI.
