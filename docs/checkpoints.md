# Verified checkpoints

- M1: CMake presets, RAII descriptors and epoll echo foundation. ASan/UBSan build and real socket echo smoke passed. The echo executable is replaced by the proxy in M3.
- M1 verification note: the first smoke attempt was sandbox-blocked; the subsequent approved run outside the sandbox passed without sanitizer diagnostics.
- M2: seven GoogleTest cases pass, covering every header split, bytewise CONNECT, framing ambiguity, limits, stripping, chunked and fixed bodies.
- M3–M9 implementation checkpoint: integrated the forwarding state machine with policy, DNS, SNI, worker isolation, authentication, limits, metrics and lifecycle together so no insecure forwarding-only binary is shipped. Sixteen unit cases and 21 real-socket integration cases pass. HTTP GET/POST/chunked, curl HTTP/HTTPS, TLS download SHA-256, fragmented ClientHello, SNI blocking, four workers, limits, reload and log checks are verified. Dedicated hardening and expanded scenario evidence follow in separate checkpoints. Initial concurrency failure was a five-entry Python backend backlog; increasing the fixture backlog to 256 made all clients succeed.
- M5–M9 expanded verification: 37 integration tests pass, including all 16 attack categories, five legitimate categories, 2,000 sockets, dual-family listeners, DNS mapping changes, an 8 MiB half-close/backpressure check, 4 MiB streaming upload, invalid reload and graceful drain. The L3 smoke download is 1 MiB; a separate benchmark runs 500 MiB.
- M10 hardening: full 37-case suite passes under ASan/UBSan and TSan. On this host TSan requires `setarch x86_64 -R` (per-process ASLR workaround). Four Valgrind integration scenarios report zero bytes at exit and zero errors. clang-tidy found one unnecessary config string copy, now corrected. Recorded a real 314-byte OpenSSL ClientHello as a unit/fuzz seed. Initial HTTP fuzz run: 697,281 executions; SNI: 1,176,277; no input-triggered crashes. Clang ASan had one pre-input startup crash with ASLR enabled; the SNI run succeeded with per-process ASLR disabled. Final reproducible runs follow after optimization.
- M11 optimization: Callgrind attributed 92,278,790 / 94,708,115 instructions (97.43%) to fixed-body framing. Replacing per-byte scans with a checked block-length subtraction reduced total instructions for the same 8 MiB accounting workload to 2,434,776. The 256 MiB framing-only timing went from 0.211128 seconds to 0.000022623 seconds; this is bookkeeping, not payload copying or network throughput. Perf was unavailable (`perf_event_paranoid=4`), so Callgrind supplied reproducible profiling evidence.
- M12 integration: the actual SentinelAgent EgressClient, subclassed only to configure the external proxy and TLS verification, completed a trusted-certificate local HTTPS request. Its existing DLP blocked a synthetic password before transmission, its destination policy blocked an unknown host, and a C++ proxy denial surfaced as an agent error. Evidence is in `bench/results/sentinel.json`; the external SentinelAgent checkout was not modified.
